# Case Study Scope

## Observed Facts

- Hermes was installed and operational.
- Persistent memory was active.
- The observed memory provider was built-in only.
- Separate memory and user profile files existed.
- `display.personality` existed but was not retained as the injection point.
- `SOUL.md` was confirmed as the primary identity file.
- An adapted charter was copied into `SOUL.md`.
- Markers appeared in `SOUL.md`.
- Offline prompt inspection found markers in the final system prompt for a fresh session.
- Initial behavior did not fully reflect the new personality.
- Behavior aligned after restart.

## Conservative Claims

This case supports a local reproducible pattern for the observed Hermes runtime. It does not prove that every local agent supports the same mechanism.

## Publication Boundaries

Public documentation uses neutral references such as `the operator`, `<project-root>`, `~/.hermes`, and `<local workstation>`.

It excludes real names, personal account names, full private paths, secrets, private identifiers, raw prompt dumps, and long raw logs.

## Future Evidence Needed

Further publication could add:

- additional runtime examples;
- adapter worksheets;
- automated privacy checks;
- reproducibility reports from clean installations;
- fresh-session behavior test templates.

Signature sentence: a useful case study says exactly what happened and exactly what it does not prove.
